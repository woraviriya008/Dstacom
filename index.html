หมวดที่ 1: สถาปัตยกรรม Transport Layer และการควบคุมความคับคั่ง

lecture06 • RFC 5681 • RFC 7323

L4 End-to-End

1.1 รากฐานและความแตกต่างของ TCP และ UDP

TCP (Byte-Stream Connection-Oriented)

• ให้บริการแบบ Byte-Stream มีการเชื่อมต่อ (3-Way Handshake) ก่อนส่งข้อมูล

• มีกลไกรับประกันความถูกต้อง (Reliability) ผ่าน Sequence และ ACK

• มี Flow Control (ปกป้องบัฟเฟอร์ฝั่งรับ) และ Congestion Control (ปกป้องเครือข่าย)

• Header Overhead: ขั้นต่ำ 20 ไบต์ (ขยายได้ถึง 60 ไบต์เมื่อมี Options)

UDP (Message-Oriented Datagram)

• ให้บริการแบบ Datagram Connectionless น้ำหนักเบา ไม่สร้างการเชื่อมต่อ

• ไม่มีการควบคุมการไหลหรือความคับคั่ง

• Header Overhead: ขนาดคงที่แน่นอน 8 ไบต์ (Src Port, Dst Port, Length, Checksum ช่องละ 2 ไบต์)

• กฎ Checksum: IPv4 เป็น Optional (ตั้งเป็น 0 ได้) แต่ใน IPv6 เป็น Mandatory (ห้ามเป็น 0 หากเป็น 0 จะถูกทิ้งทันที)

การจัดสรรหมายเลขพอร์ต IANA (0 – 65,535):
Well-Known (0 – 1,023) ระบบมาตรฐาน สงวนสิทธิ์เฉพาะ Root/Privileged ในการ Bind
Registered (1,024 – 49,151) สำหรับแอปพลิเคชันทั่วไป ไม่ต้องใช้สิทธิ์พิเศษ
Dynamic / Private (49,152 – 65,535) สุ่มใช้เป็น Ephemeral Ports ชั่วคราวฝั่งไคลเอนต์

1.2 วงจรการเชื่อมต่อและ State Machine ของ TCP

TCP 3-Way Handshake & ISN Selection:

• ขั้นตอน: Client SYN(seq=x) ➔ Server SYN+ACK(seq=y, ack=x+1) ➔ Client ACK(seq=x+1, ack=y+1)

• สุ่ม ISN: ต้องสุ่มเลือกแยกกันเป็นอิสระ แทนที่จะเริ่มที่ 0 เสมอ เพื่อป้องกันแพ็กเก็ตตกค้าง (Delayed Duplicate Segments) จากเซสชันเก่าข้ามมารบกวน

• ธง SYN และ FIN ใช้ Sequence Number เสมือน 1 ไบต์เสมอ

TCP 4-Way Teardown & Half-Close:

• ฝั่งปิดก่อน (Active Close) ส่ง FIN (เข้าสู่ FIN_WAIT_1) ➔ ฝั่งรับตอบ ACK (เข้าสู่ CLOSE_WAIT ฝั่งส่งเข้า FIN_WAIT_2)

• สภาวะ Half-Close: ฝั่งที่อยู่ในสถานะ CLOSE_WAIT ยังสามารถส่งข้อมูลที่ค้างในบัฟเฟอร์ต่อไปได้จนจบ ก่อนจะส่ง FIN ของตนเอง (เข้าสู่ LAST_ACK)

บทบาทของสถานะ TIME_WAIT (2MSL):

ฝั่ง Active Close ต้องคงอยู่ในสถานะ TIME_WAIT เป็นระยะเวลา $2\text{MSL} \approx 120$ วินาที เพื่อ: (1) รับประกันว่า ACK สุดท้ายส่งถึงปลายทาง (หากหายจะตอบซ้ำเมื่ออีกฝ่ายส่ง FIN มาใหม่) และ (2) ปล่อยให้แพ็กเก็ตตกค้างทั้งหมดสลายตัวจนหมดสิ้น

TCP RST (Reset) Triggers:

สร้างและส่ง Segment แฟล็ก RST ทันทีเมื่อ: มีแพ็กเก็ตส่งมายังพอร์ตที่ไม่มี Listening Socket หรือ Process ใดเปิดรับอยู่ ช่วยตัดปัญหาและแจ้งฝั่งส่งทันที (Connection Refused)

1.3 Flow Control & Congestion Control (RFC 5681)

Flow Control vs Congestion Control

• Flow Control: ปกป้องบัฟเฟอร์โฮสต์ฝั่งรับ โดยใช้หน้าต่าง rwnd

• Congestion Control: ปกป้องเครือข่ายและเราเตอร์คอขวด โดยใช้หน้าต่าง cwnd

• ปริมาณข้อมูลค้างส่งจริง: $\text{Effective Window} = \min(cwnd, rwnd)$

Silly Window Syndrome (SWS) & Clark

• ปัญหา: แอปฝั่งรับดึงข้อมูลทีละน้อย ทำให้โฆษณา Window เล็ก เปลือง Overhead

• Clark's Solution (ฝั่งรับ): ระงับการโฆษณา Window Update ไว้จนกว่าจะมีที่ว่างอย่างน้อย 1 MSS เต็ม หรือครึ่งหนึ่งของบัฟเฟอร์ทั้งหมด

Nagle's Algorithm vs Delayed ACK Interaction

• ฝั่งส่ง Nagle กักแพ็กเก็ตเล็กไว้จนกว่าจะได้ ACK หรือเต็ม MSS ขณะที่ Delayed ACK ฝั่งรับหน่วงเวลาส่ง ACK นานถึง ~200ms

• ส่งผลให้เกิด Temporary Deadlock ใน Interactive Apps แก้ไขโดยปิด Nagle ด้วย Socket Option: TCP_NODELAY

สรุปสูตรคำนวณสำคัญ (Transport Layer):
1. BDP (bits) = R (bps) × RTT (sec)
Buffer_min (Bytes) = BDP / 8
2. Clark Update Threshold =
min( MSS, Buffer_Total / 2 )
3. Fast Recovery (RFC 5681):
ssthresh_new = max( FlightSize / 2, 2 × MSS )
cwnd_recovery = ssthresh_new + 3 × MSS
4. Seq Wrap Time (T_wrap):
T_wrap = (2^32 Bytes) / (Rate Bytes/sec)
* แก้ไขปัญหาด้วย PAWS (RFC 7323)

หมวดที่ 2: สถาปัตยกรรม Network Layer, IPv4/IPv6 และการกำหนดเส้นทาง

VLSM • IPv6 Basics (RFC 5952) • SLAAC • NDP • OSPF

L3 Hop-by-Hop

2.1 IPv4 Addressing, Subnetting และ Packet Forwarding

VLSM Subnet Planning

• คำนวณจาก: $2^h - 2 \ge \text{Hosts}$ (หัก 2 สำหรับ Network และ Broadcast)

• ความยาว Prefix: $/(32 - h)$ | ขนาดบล็อก: $2^h$

IPv4 Fragmentation

• หัก IPv4 Header 20 ไบต์: $\text{Payload} = \lfloor (\text{MTU} - 20) / 8 \rfloor \times 8$ (ต้องหาร 8 ลงตัว)

• ชิ้นส่วนไม่สุดท้าย $\text{MF}=1$ | ชิ้นสุดท้าย $\text{MF}=0$

• $\text{Fragment Offset} = (\text{ไบต์สะสมก่อนหน้า}) / 8$

Longest Prefix Match (LPM Invariant) & AD

• กฎ LPM: เราเตอร์เลือกเส้นทางที่มี Prefix ยาวที่สุดและเจาะจงที่สุดเสมอ (/25 ชนะ /24 ชนะ /0) โดย LPM อยู่เหนือ Metric และ AD ในขั้นตอน Forwarding จริง

• Administrative Distance (AD): ใช้ตัดสินว่าจะบันทึกเส้นทางจาก Routing Protocol ใดลง Routing Table เมื่อ Prefix ซ้ำกัน (Connected=0, Static=1, OSPF=110, RIP=120)

2.2 สถาปัตยกรรม IPv6 และมาตรฐาน RFC

IPv6 Base Header & Chaining

• ขนาดคงที่ 40 ไบต์เสมอ ไม่มี Header Checksum

• Extension Headers เชื่อมต่อผ่านฟิลด์ Next Header เราเตอร์ข้ามได้โดยไม่ต้องตรวจ (ยกเว้น Hop-by-Hop)

• ข้อห้าม: เราเตอร์ห้ามทำ Fragmentation เด็ดขาด หากเกิน MTU ให้ส่ง ICMPv6 Type 2 (Packet Too Big) กลับไปทำ PMTUD

Address Scopes & การย่อรูป (RFC 5952)

• Link-Local (fe80::/10): ใช้บนลิงก์เดียวกัน ไม่ข้ามเราเตอร์

• Anycast: ส่งหาโหนดที่ใกล้ที่สุดตาม Metric (ใช้ใน CDN / Root DNS)

• ตัด Broadcast ทิ้ง โดยแทนที่ด้วย Multicast (ff00::/8)

• ตัดเลข 0 ด้านหน้า Hextet ทิ้งได้ และใช้ :: ย่อกลุ่ม 0 ต่อเนื่องยาวสุดได้เพียงครั้งเดียว

2.3 SLAAC, IEEE EUI-64, NDP และ Subnetting

SLAAC & Prefix /64 Boundary: รับ Prefix 64 บิตจาก Router Advertisement (RA) มารวมกับ Interface ID (IID) 64 บิต หากผู้ดูแลแบ่งซับเน็ตเป็น /80 ระบบ SLAAC จะพังทันที
IEEE EUI-64 Interface Identifier: (1) แทรก FF:FE ตรงกลาง MAC 48 บิต (2) กลับบิตที่ 7 ของไบต์แรกสุด (00 ➔ 02, c0 ➔ c2) เช่น c0:c1:c2:c3:c4:c5 ➔ c2c1:c2ff:fec3:c4c5
ICMPv6 Neighbor Discovery Protocol (NDP): ส่ง Neighbor Solicitation (NS) ไปยัง Solicited-Node Multicast (ff02::1:ffxx:xxxx) แปลงเป็น L2 Multicast MAC (33:33:ff:xx:xx:xx) ให้ NIC คัดกรองทิ้งในระดับฮาร์ดแวร์ | แพ็กเก็ต DAD ใช้ Source IP เป็น ::
Subnetting /48 to /64 & Transition: ได้ $2^{16} = 65,536$ ซับเน็ต (ลำดับที่ 75 = 0x4b ได้ 2001:db8:acad:4b::/64) | กลไกเปลี่ยนผ่าน: Dual-Stack, Translation (NAT64/DNS64), Tunneling (6in4, 6to4, GRE)

หมวดที่ 3: Data Link Layer, การทำงานของ Switch และงบประมาณเวลาหน่วง

Collision & Broadcast Domains • MAC Table • Delay Budget • MSS

L1 – L2

3.1 การทำงานของ Ethernet Switch และ ARP

Hub (Layer 1) 1 Collision Domain รวมทุกพอร์ต และ 1 Broadcast Domain รวมทุกพอร์ต
Switch (Layer 2) แยก Collision Domain อิสระในแต่ละพอร์ต แต่ยังคงอยู่ใน 1 Broadcast Domain ต่อ 1 VLAN
Router (Layer 3) ตัดและแบ่งแยกทั้ง Collision Domain และ Broadcast Domain ในทุกพอร์ต
MAC Table & Header Rewriting:

• สวิตช์เรียนรู้จาก Source MAC และ Ingress Port; หากทราบ Destination MAC จะส่งแบบ Selective Forwarding แต่หากไม่ทราบ (Unknown Unicast) จะทำ Flooding ออกทุกพอร์ตยกเว้นพอร์ตที่รับเข้ามา

• เมื่อเฟรมข้ามเราเตอร์: L2 MAC Header จะถูกเขียนใหม่ในทุกๆ Hop ขณะที่ L3 IP และ L4 Ports จะคงเดิมตลอด End-to-End (ค่า TTL ลดลง 1)

• RSTP (802.1w) บรรจบลิงก์ใหม่ได้ใน ~1 วินาที ทำให้เซสชัน TCP ไม่ขาดหาย

ส่วนประกอบ ขนาด Header / MTU บทบาทสำคัญ
Ethernet (Layer 2) 14 ไบต์ (+ FCS 4 ไบต์) Src MAC (6B), Dst MAC (6B), Type (2B) ไม่นับเป็นส่วนของ MTU
IPv4 Header 20 ไบต์ (ขั้นต่ำ) ขยายได้สูงสุด 60 ไบต์หากมี Options
IPv6 Header 40 ไบต์ (คงที่) ขนาดตายตัว ไม่มี Header Checksum
TCP Header 20 ไบต์ (ขั้นต่ำ) ขยายได้เมื่อมี Options (เช่น Timestamps)
UDP Header 8 ไบต์ (คงที่) ประกอบด้วย 4 ฟิลด์ ฟิลด์ละ 2 ไบต์
Standard / Jumbo MTU 1,500 / 9,000 ไบต์ Payload สูงสุดของเฟรม L2 (ไม่รวม L2 Header 14B)
สูตรคำนวณ Latency Budget & MSS:

• d_trans = L (bits) / R (bps) | d_prop = D (m) / v (m/s) [v ในใยแก้ว ≈ 2×10^8 m/s = 200 km/ms]

• IPv4 MSS = MTU - 40 | IPv6 MSS = MTU - 60 (Jumbo Frame MTU 9,000B: IPv4=8,960B, IPv6=8,940B)

หมวดที่ 4: Application Layer Protocols และสถาปัตยกรรมเว็บ

DNS • HTTP/1.0–3 • FTP (RFC 959) • Telnet

L7 Application

4.1 Domain Name System (DNS)

Recursive vs Iterative

• Recursive: ภาระอยู่ที่ Local Resolver ในการหาคำตอบจนได้ IP

• Iterative: เซิร์ฟเวอร์ตอบชี้แนะ (Referral / Next Name Server)

• ลำดับสืบค้น: Root (.) ➔ TLD (.th) ➔ Authoritative (wu.ac.th)

Resource Records & กฎเหล็ก

• A (IPv4), AAAA (IPv6), PTR (Reverse Lookup)

• CNAME Invariant: ชื่อใดมี CNAME ห้ามมีระเบียนอื่นซ้ำเด็ดขาด

• MX: เลข Preference ยิ่งน้อย ยิ่งสำคัญสูงสุด (5 สำคัญกว่า 10)

การสลับ UDP vs TCP พอร์ต 53: ปกติใช้ UDP 53 แต่สลับไปใช้ TCP 53 เมื่อ: (1) มีการทำ Zone Transfer (AXFR/IXFR) หรือ (2) คำตอบมีขนาดเกิน 512 ไบต์ โดยเซิร์ฟเวอร์ตั้งแฟล็ก TC (Truncated) ให้ถามใหม่ทาง TCP

4.2 Hypertext Transfer Protocol (HTTP)

วิวัฒนาการ HTTP

• HTTP/1.0: Non-persistent ปิด TCP ทุกไฟล์ เสียเวลา $(1+N) \times 2\text{ RTT}$

• HTTP/1.1: Persistent ใช้ TCP Handshake ร่วมกัน (Pipelined ใช้ $3\text{ RTT}$)

• HTTP/2: Multiplexing บน TCP เดียว (ยังติดปัญหา TCP HoL Blocking)

• HTTP/3: QUIC บน UDP แยกการกู้คืนสตรีมเป็นอิสระ

Conditional Caching & Idempotency

• คำขอ If-None-Match: "ETag" ตอบ 304 Not Modified โดยมี Body Size = 0 ไบต์

• Idempotent Methods: GET, HEAD, PUT, DELETE

• Non-Idempotent: POST (เรียกซ้ำอาจเกิดข้อมูลซ้ำซ้อน)

4.3 FTP (RFC 959) และ Telnet

FTP Dual-Channel & Active vs Passive:

• Control Connection (TCP 21) สำหรับส่งคำสั่ง (Out-of-band เช่น ABOR) และ Data Connection ส่งไฟล์จริง

• Active Mode (Server Inbound มักถูกไฟร์วอลล์บล็อก) vs Passive Mode (Client Outbound ทะลุไฟร์วอลล์ได้)

• สูตรคำนวณหมายเลข Data Port: จากรหัส 227 (..., p1, p2) ➔ Data Port = (p1 × 256) + p2

Telnet vs SSH & Control Commands:

• Telnet (TCP 23) วิ่งเป็น Plaintext ไม่เข้ารหัสใน TCP Payload ต่างจาก SSH (TCP 22) ที่เข้ารหัสแบบ End-to-End

• รหัสไบต์ 255 (0xFF) คือ IAC (Interpret As Command) | คำสั่ง WILL (เปิดใช้เอง) vs DO (ขอให้อีกฝ่ายเปิด)

5.2 เทคนิคการตัดทอนตัวเลขด้วยมือ (No Calculator Strategy)

1. การคูณแบนด์วิดท์กับเวลา RTT (BDP & Buffer Calculation):

ฝึกจัดกลุ่มเลขยกกำลังฐานสิบและฐานสอง โดยแปลงหน่วยมิลลิวินาที (ms) เป็นวินาที ($\text{ms} = 10^{-3}\text{ s}$) ก่อนนำไปตัดกับแบนด์วิดท์ Mbps ($10^6\text{ bps}$):

ตัวอย่างโจทย์: Bandwidth = 50 Mbps, RTT = 20 ms
BDP (bits) = (50 × 10⁶ bps) × (20 × 10⁻³ s) = 50 × 20 × 10³ = 1,000,000 บิต
แปลงเป็นไบต์ (Buffer_min): 1,000,000 / 8 = 125,000 ไบต์
2. การคำนวณ Propagation Delay ในสายใยแก้วนำแสง:

ใช้ค่าคงที่ความเร็วคลื่นแสงในตัวกลางใยแก้ว: $v \approx 2 \times 10^8\text{ m/s} = 200,000\text{ km/s} = 200\text{ km/ms}$ (หรือ $200\text{ m/}\mu\text{s}$) แทนค่าตัดตัวเลขได้ทันที:

ตัวอย่างโจทย์: ระยะทางสายไฟเบอร์ D = 1,000 km
d_prop = Distance / Velocity = 1,000 km / (200 km/ms) = 5 ms

5.3 การแปลงเลขฐานสองและฐานสิบหก (Base Conversion Shortcuts)

การแปลงดัชนีซับเน็ต IPv6 (Decimal ➔ Hexadecimal):

แยกตัวเลขฐานสิบออกเป็นผลบวกของค่าประจำหลักฐานสิบหก ($16^1 = 16, 16^0 = 1$):

ลำดับที่ 75₁₀:
75 ÷ 16 = 4 เศษ 11
4₁₀ = 4₁₆, 11₁₀ = B₁₆ ➔ 75₁₀ = 0x4B
ได้แอดเดรส: 2001:db8:acad:4b::/64
การกลับบิตที่ 7 ของไบต์แรกใน EUI-64 (U/L Bit):

กระจายเฉพาะไบต์แรกสุดของ MAC Address เป็นเลขฐานสอง 8 บิต แล้วกลับบิตที่ 7 (นับจากซ้าย):

ค่า 00₁₆ = 0000 0000₂ ➔ 0000 0010₂ = 02₁₆
ค่า c0₁₆ = 1100 0000₂ ➔ 1100 0010₂ = c2₁₆
ค่า 08₁₆ = 0000 1000₂ ➔ 0000 1010₂ = 0a₁₆

15 ทริคพิชิตข้อสอบ & จุดดักคะแนนยอดฮิต (Exam Traps)

สรุปจุดที่นักศึกษามักจำสับสนและจุดที่ข้อสอบชอบนำมาหลอก

Top Pitfalls
1. UDP Checksum ใน IPv6 L4/L3

ใน IPv4 เป็น Optional (ตั้งเป็น 0 ได้) แต่ใน IPv6 ถูกบังคับเป็น Mandatory อย่างเด็ดขาด หากพบ Checksum เป็น 0 ใน IPv6 แพ็กเก็ตจะถูกทิ้งทันที

2. SWS Clark vs Nagle L4

Clark's Solution ทำงานที่ฝั่งรับ (Receiver) เพื่อกักการโฆษณา Window ส่วน Nagle's Algorithm ทำงานที่ฝั่งส่ง (Sender) เพื่อกักแพ็กเก็ตเล็ก

3. SLAAC Subnet /64 Boundary L3

สถาปัตยกรรม SLAAC บังคับใช้ Prefix สำหรับ Subnet ขนาด /64 เท่านั้น หากโจทย์หลอกว่าแบ่งซับเน็ตเป็น /80 คำตอบคือ SLAAC จะล้มเหลวทันที

4. LPM ชนะทุกสิ่งในการ Forwarding L3

เมื่อแพ็กเก็ตมาถึงเราเตอร์ กฎ Longest Prefix Match (LPM) (/25 ชนะ /24 ชนะ /0) จะตัดสินก่อนเสมอ ไม่ว่าเส้นทางนั้นจะมี Metric หรือ AD ใด

5. การกลับบิตที่ 7 ใน EUI-64 L3

สูตรลัดเลขฐานสิบหกไบต์แรก: 00 ➔ 02, c0 ➔ c2, 08 ➔ 0a (กลับเฉพาะบิตที่ 7 นับจากซ้าย)

6. การคำนวณ FTP Passive Port L7

จากรหัส 227 (..., p1, p2): สูตรคือ (p1 × 256) + p2 ห้ามสลับตัวแปรและห้ามคูณด้วย 255

7. CNAME Exclusivity Rule L7

โดเมนใดที่มีระเบียน CNAME แล้ว ห้ามมีระเบียน A, AAAA, หรือ MX ในชื่อเดียวกันซ้ำเด็ดขาด

8. DNS MX Preference Number L7

สำหรับระเบียน MX ค่าตัวเลขยิ่งน้อย ยิ่งมีความสำคัญสูงสุด (Preference 5 มาก่อน Preference 10)

9. Fragment Offset ต้องหาร 8 L3

ค่า Fragment Offset ใน Header มีหน่วยเป็น บล็อก 8 ไบต์ ดังนั้นขนาดข้อมูลแต่ละชิ้น (ยกเว้นชิ้นสุดท้าย) ต้องหาร 8 ลงตัวเสมอ

10. TCP MSS หัก Header ต่างกัน L4/L3

ใน IPv4: MSS = MTU - 40 (IP 20 + TCP 20) แต่ใน IPv6: MSS = MTU - 60 (IPv6 40 + TCP 20)

11. ความเร็วแสงในใยแก้วนำแสง L1

ความเร็วคลื่นในสายใยแก้วคือ $v \approx 2 \times 10^8\text{ m/s} = 200\text{ km/ms}$ ไม่ใช่ $3 \times 10^8$ m/s

12. Source IP ในแพ็กเก็ต DAD L3

แพ็กเก็ต Neighbor Solicitation ที่ส่งเพื่อทำ Duplicate Address Detection (DAD) ต้องใช้ Source IP เป็น :: (Unspecified)

13. HTTP 304 Body Size L7

เมื่อเซิร์ฟเวอร์ตอบกลับด้วย 304 Not Modified ขนาดของ HTTP Body Payload จะเป็น 0 ไบต์เสมอ

14. ข้ามเราเตอร์ L2 เปลี่ยน L3/L4 คงเดิม L2/L3

เมื่อแพ็กเก็ตข้ามเราเตอร์: Src/Dst MAC ถูกเขียนใหม่ทุก Hop ส่วน Src/Dst IP และ Port จะคงที่ตลอด End-to-End

15. Fast Recovery Exit cwnd Value L4

เมื่ออยู่ใน Fast Recovery แล้วได้รับ New Cumulative ACK ค่า cwnd จะยุบตัวกลับลงมาเท่ากับ $ssthresh$ ทันที
